## The loop

1. A session changes what Verse can do.
2. It runs `node tools/grow.mjs <kind> "what changed"`, commits, pushes (`node tools/push.mjs`).
3. The PR merges once green and main deploys. The entry is live and summonable within about a minute of that.
4. Nothing else needs to happen. No board update, no Notion, no Slack post — the ledger is the record. If a Slack line to #ops-runs is still wanted, it is a one-line `git` hook, not a second source of truth.

The ledger starts with 162 entries copied from the `grow`, `build`, `ship`, `review` and `fix` lines of `domains/void.agents.log.md` (each marked `"from": "domains/void.agents.log.md"`).

Any script on the page can summon the same way the old void-proxy command bar did:
`document.dispatchEvent(new CustomEvent('void:summon', { detail: 'growth' }))` runs that ask as if it were typed.

The crowd on the is-it card and "invite someone" both run on the `ShareRoom` Durable Object in `share-worker/`. The code is on main, but the Pages project
is not bound to it yet, so `/api/share/<room>` answers 503 "not switched on yet" and the page falls back to tabs in one browser. Two owner steps switch it on:
1. Repo secret `CLOUDFLARE_WORKERS_TOKEN` (an API token with only *Workers Scripts: Edit*): `deploy-workers.yml` then deploys `void-share` on every merge that touches it (or run the workflow by hand once).

### 3. The cliffs: what breaks first at ten times today's traffic, and how anyone would notice

Ranked by how close Verse already stands to the line. None of them is logged in the repo as the line being crossed; the signs are indirect.

1. **Workers AI's 10,000 neurons a day.** Card art alone books about 30% of the day before anyone asks a question; answers, the review on every PR, the hourly will and the 2-hourly fix share the rest. At ten times the asks the day's allocation is gone by the afternoon UTC and every `env.AI.run` throws until midnight. What a person sees: `/api/answer` still answers 200, from the second-try model, then from the open web (the Wikipedia extract) with `note: 'model busy'`, so answers go flat and sourced rather than failing; `/api/card-art` answers 200 `{state:'plate', why:'cap'}` (Verse's ink plate) or a Pollinations picture; `/api/reflect` answers 503 "Verse could not answer just now"; the `void-review` check on a PR falls back to its rule-only findings or fails, and automerge waits. Where it shows: `void_shortfalls` rows with `reason = 'free limit'` (read by `/api/earnings` and `tools/will.py`), `void_art_miss` rows, the step summary of `void-review.yml`, and the neuron graph at dash → AI → Workers AI. Nothing alerts; a run that reads `void_shortfalls` is the only watcher.
2. **D1's 100,000 rows written a day (then 5 million read).** The tally alone may write 20,000 a day; misses, reactions, ticks, art, sessions and the queue write the rest, and the old Workers' databases count on the same meter. Past the line every write throws "exceeded D1's free tier daily row write limit": `/api/miss` and `/api/misses` answer 503 "miss list unavailable" or "use count unavailable", `/api/routines` 503 "routines unavailable", `/api/tally` 503 "the tally is off for now", `/api/react` 503 "reactions are off for now", passkey sign-in fails, and `answer.js`'s cache write is swallowed (`.catch(() => {})`) so answers keep flowing but nothing learns. Reads go second: `/api/misses` scans the whole miss table and `card-art` counts the whole `void_art` table on every POST, so at ten times the POSTs the read meter climbs with the table. Where it shows: Cloudflare's own email to the account, the D1 Metrics page; in the repo only as a run of 503s in the site tester's issues (`site-test` label) and Verse's "looked and found nothing" findings. Stored data is safe either side of the line.
3. **The 100,000 Workers and Pages Functions requests a day, shared with 62 Workers that are not Verse.** A page load is up to 26 `/api` calls before a single skill runs; the clock, the site test, the will and the probes add a few thousand a day on their own. At ten times the visitors (or one scraper on `/api/answer`, which the guard's per-connection limit does not stop across many connections) the pool empties and every `/api` call answers Cloudflare's **Error 1027** HTML page for the rest of the UTC day, while the stage itself still loads because static files are free. What a person sees: the page opens, every card that calls `/api` gets HTML where it expected JSON and falls to its offline fallback, the clock's knocks are refused (the `Tick refused` warning in `void-tick.yml`), MCP live fails and `live-revert.yml` opens a revert PR for a commit that broke nothing. Where it shows: dash → Workers & Pages → a-to-mind → Metrics (requests and errors), and the account overview for the shared total.
