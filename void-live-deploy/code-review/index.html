Verse reviews every pull request the moment it opens: the bugs, security holes and risky habits in the lines you added, each one on its line with a one-click fix where a safe one exists, and a merge gate that holds a PR until they're fixed.

Add it to a repository

Save this as .github/workflows/void-review.yml. Every pull request gets a walkthrough of what changed, the findings, and inline comments with suggested fixes.

on: pull_request
permissions: { contents: read, pull-requests: write }
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: atomeam/void-loop/review@main
        with:
          gate: 'true'                               # fail the check on bugs and risks
          void-key: ${{ secrets.VOID_REVIEW_KEY }}   # Verse Pro: the closer read (optional)

A line that is right as written can say so with a void-review: ok comment, and the gate leaves it out.

The API

curl -s https://a-to-mind.com/api/review \
  -H 'content-type: application/json' \
  -H "authorization: Bearer $VOID_REVIEW_KEY" \
  -d '{"code": "if (x = 5) { go() }"}'

Leave out the authorization line for the free checks.

Send {"code": …} or a unified diff as {"diff": …} (then only the added lines are checked, with the new file's line numbers). You get findings (line, kind, rule, message) and, with a Code Review Pro license key (or a key from Verse Pro), the closer read in answer.

From your AI (MCP)

Verse is an MCP server at https://a-to-mind.com/api/mcp, so Claude, ChatGPT or any agent can call the review itself. In Claude Code:

claude mcp add --transport http void https://a-to-mind.com/api/mcp \
  --header "Authorization: Bearer $VOID_REVIEW_KEY"

Or in any client's config:

{ "mcpServers": { "void": { "type": "http", "url": "https://a-to-mind.com/api/mcp",
  "headers": { "Authorization": "Bearer YOUR_REVIEW_KEY" } } } }
