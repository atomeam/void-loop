# Handoff: who is building what

The owner, 2026-10-15: "Don't just stay out of each other's way ... build ladders for each other, meaning tools, notes and fixes that make the other one faster, so we both climb higher." Every agent working on Verse (the hourly builder, owner-driven Claude sessions, the parallel/live/voice agent) reads this before starting and writes to it before pushing. Nobody steps on anybody; nothing gets done twice. This is the one board (it absorbed `docs/TAGTEAM.md` on 2026-10-15). The other workers, the video player, the everything-app verticals (social, dating, crypto, delivery) and the video engine, log here too.

## How to use it

- **Before you start:** read **Working on** below. If your item is there and its line is under a day old, pick something else, or write under it what you would add and leave it to them.
- **When you start:** add one line under **Working on**: `- <who> · <branch> · <what> · <date time UTC>`. Use a branch name nobody has used: check `git ls-remote origin "refs/heads/<branch>"` is empty first.
- **When you ship:** move your line to **Just finished** with the PR link, and add anything the next agent could take to **Up for grabs**.
- **When you solve something annoying** (a deploy step, test setup, a guard, a tool flag), leave a script or a playbook (`docs/playbooks/`) and one line under **Ladders** so nobody solves it twice.
- **Second eyes:** glance at the other's open PRs for bugs before they merge and comment on a real one. It is a look, not an approval.
- **Verse reads it:** `tools/self-context.mjs` puts Just finished, Ladders and Lessons (trimmed) into self.json `builders`. Write those as one-line bullets `- **name**: line`, newest first. Nothing owner-only or private: the repo is public.
- **Sharing the tree:** `git pull --rebase` before every push; never force-push.
- **By strength (owner, 2026-10-15):** Claude sessions take deep code work and reviews; the parallel agent takes parallel tracks, live checks, deploys and Verse's voice loop. Hand off here at clear points.

## Lessons

- **A new page says what it takes and gives**: add `<meta name="verse-handoff" content="in: ...; out: ...">` when it ships (types in `tools/handoff-scan.mjs`); every lap builds the top connections in `docs/HANDOFF-GAPS.md` and plays them in `tools/handoff-e2e.mjs` (standing item in docs/NEXT.md).
- **The gate's standards (owner, 2026-10-28; docs/GATE-STANDARDS.md)**: a floor is beaten only by scripted end-to-end journeys against the competitor, each with negative controls (no stub, placeholder, error page or "coming soon"). A check that is blocked, skipped, walled or fails to load is INCOMPLETE, never a pass; a rival Verse could not read never counts as "0 of N". Every false pass gets an adversarial fixture in tools/tower-falsepass.test.mjs (Amazon's 11 of 13 and YouTube's "replaced" first). No mock or static data in a production path without a visible degradation notice (tools/no-mock.mjs). Fix the bug, never weaken the test.
- **Rumble's page id is not its embed id**: rumble.com/v77xmv8-… embeds as /embed/v75qyv0; ask Rumble's oEmbed (/api/video?url=) instead of guessing.
