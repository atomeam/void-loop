## Working fast (learned 2026-10-04)

- `node tools/checks.mjs` runs every fast check in one go (fringe ledger, skill collisions, calendar, glyphs, void.html matching its two deploy copies, the full benchmark against its floor, the miss reader's redaction). Run it before every push; CI runs the full browser suite. The benchmark is not replayed when nothing it reads has changed since its last passing run (a hash of the served files, bench.json, the browser and the day; `node tools/bench.mjs --score --fresh` forces it), and it waits for each answer instead of sleeping a fixed time, so a change that never touches the page costs nothing and a full replay is far shorter than the old 20 minutes. Add your test on its own line in the list at the top of `tools/checks.mjs` (one entry per line, so two PRs adding tests do not conflict).
- Checks run on the merged head, not before merging main (2026-10-10): merge main first (`node tools/merge-main.mjs`, never by hand), then run `node tools/checks.mjs`, then push. #291 ran its checks, then hand-merged main with the growth ledger still conflicted and pushed; the merge was automerged 40 seconds later and the live growth card could not read its ledger until #297. Conflict markers are now a bug in Void's review on any file type, a `markers` row in checks.mjs, and merge-main.mjs refuses to commit while any tracked file has one.
- `VOID_SKIP_BENCH=1 node tools/checks.mjs` before a push (2026-10-10, owner): the benchmark is not a merge gate. The bench job on the PR (`.github/workflows/bench.yml`) reports the number, and a drop below the floor is a fix PR, never a wait. `tools/test_void.mjs` honours the same variable. Plain `node tools/checks.mjs` still replays it when you want the number locally.
- The floor rises on its own after each clean bench on main (2026-10-10): `.github/workflows/bench.yml` runs the benchmark on main once a day when main has moved (or by hand: `gh workflow run bench.yml --ref main`), and when the score minus 5 is above `tools/bench.best.json` it commits the new floor to main (`tools/bench-floor.mjs`, tested in `tools/bench-floor.test.mjs`), never lowering it. A drop below the floor is a fix PR. A benchmark ask that misses is read from its loop log and run through `tools/ask.mjs` before it is called flaky (the setup's own Escape was a double-Esc undo once).
- `node tools/bench.mjs --probe candidates.json` tries a batch of new asks (same shape as tools/bench.json) and prints only the misses. Probe 30–40 at once, fix the misses, then add the batch with `node tools/append.mjs bench --skip candidates.json` (the same file). After a fix, `node tools/bench.mjs --again` re-probes only the asks the last probe missed. For review asks, `says` is checked with the pasted code taken out of the card first, so a pattern that only appears in the code no longer passes.
- Push with `node tools/push.mjs`: it retries when GitHub errors (a 500 can leave the old head in place) and only says "pushed" once origin really has your commit.
- Never wait on CI, and never sit watching a PR. Push, then `node tools/automerge.mjs <pr> --label` and move on: GitHub merges it by itself (.github/workflows/automerge.yml, tools/pr-ready.mjs) as soon as Void's own review check (`void-review`, seconds) is clean on the current head and nothing that already finished failed. Ship now, test after (2026-10-09): nothing else is waited on, not the suite, not the bench. Void's review is the main one; CodeRabbit and any other reviewer are extras: reported, never waited on, never blocking. A real bug an extra caught that Void missed is a rule to add to code-review.js (with a case in review.test.mjs), so Void's review keeps getting better. After merging it starts the deploy of main itself; main deploys in about a minute, then the full suite runs on what shipped (deploy.yml `verify-main`) and a failure reverts the commit that broke the failed checks (tools/revert-target.mjs: not always the one just tested; when unclear it reports instead of guessing) and redeploys. So run `node tools/checks.mjs` before you push: a red suite after merge costs a revert. `node tools/merge-when-green.mjs <pr>` is the same check polled from a session, for when you want to watch it happen.
- A PR that conflicts with main gets no `pull_request` runs at all: GitHub skips them, so a labelled PR could sit silently forever (learned on #270, 2026-10-10). automerge.yml now merges main into labelled PRs from this repository itself (`tools/merge-main.mjs` from main's checkout settles the append-only files), pushes the merge commit to the branch (never forced) and starts Void's review on the new head (a push made with the workflow's token starts no run on its own; `void-review.yml` takes a `pr` input for that). A conflict outside the append-only files comes back as one comment on the PR naming the files: run `node tools/merge-main.mjs` on the branch, resolve them, push. Nothing to do by hand when both sides only appended.
- A new push to a PR cancels the older run of that PR (deploy.yml: the per-PR concurrency group with cancel-in-progress); on a PR the benchmark runs as its own job, in parallel with the suite. On main, every merge gets its own verify-main run (one concurrency group per head, 2026-10-10): nothing is superseded, the suites run in parallel, and a revert is taken only while its target is still live on main and the failed checks are still red on main's newest verified head (tools/revert-target.mjs).
- What a run builds (2026-10-08): first read Void's own asks (`node tools/reflect.mjs`, mirrored at the top of `domains/void.voice.md`) and weigh them heavily: a concrete ask from Void gets built next, and the agent log line and commit say "asked by Void". Then real misses (`node tools/misses.mjs`), then an open inbox row, then the top unfinished Next item. Ship one useful skill or a real improvement to one, and add bench asks only for the behaviour you changed. Asks invented to fill the bench no longer count as progress: run 47 added 23 and all passed on the first probe. If none of those is actionable, take the top unclaimed item in `domains/void.frontier.md` (2026-10-09: "we should not sit still"): ship its smallest visible piece and write the next step on it. A run never ends on "no work found".
- Everyday maths and unit asks now pass on the first probe (run 36: 32 of 32), so spend probes where Void is thinner: review asks in more languages, places and times, words and definitions, and phrasings people actually type. `bench.mjs --probe` skips asks the bench already has.
- `node tools/ask.mjs "ask" …` shows what Void answers for each ask (who answered, the card text, any page error such as a TDZ crash) with outside services blocked. Use it when a probe misses for no clear reason.
- Every new unauthenticated POST endpoint gets one hostile read before its label: ask "what could a stranger make this do?" (queue jobs, spend model budget, write rows, send anything) and add the limit or check that answers it.
- Void reviews code, and it reviews every PR first. `void-live-deploy/lib/code-review.js` holds the checks (bugs, risks, style, safe automatic fixes) the site runs when someone asks "review this code", and `tools/review.test.mjs` tests them, including a speed budget (a regex that backtracked once made one file take minutes). `node tools/review-pr.mjs [--base origin/main] [--gate]` runs them on the lines a branch adds in about a second; run it before pushing. The `void-review` check (.github/workflows/void-review.yml) posts the review and fails while the added lines carry a bug or a risk: fix it, or mark a line that is right as written with a `void-review: ok` comment. A false positive is a bug in code-review.js, so fix the rule and add a case to the test. It is also a product, the first in `void-live-deploy/lib/products.js` (Void's standalone products, each also included in the $49 Void): the page https://a-to-mind.com/code-review/, the API `/api/review` (functions/api/review.js, lib/review-api.js: free instant checks; the closer read for a Code Review Pro license key, a key from paid Void, or the owner) and the GitHub Action `atomeam/void-loop/review@main` (inputs `gate`, `void-key`). It stays free for us: the owner key never pays and has no daily cap, and our own void-review check uses it.
- `node tools/merge-main.mjs` merges origin/main and settles the append-only files (bench.json, grown.json, the agent log) by keeping both sides.
- `node tools/misses.mjs` reads the real miss board (owner-only /api/misses, needs VOID_MISSES_TOKEN). It only prints: this repo is public, so raw asks never get committed.
- `node tools/fringe.mjs --record <draft> <sources.json>` adds a fringe run in the ledger's own style; after fixing a recorded draft (a review finding), `node tools/fringe.mjs --rehash <draft>` refreshes its sha256.
- `node tools/draft-check.mjs [draft.html]` opens fringe drafts headless (by default the ones this branch changes) and fails on a missing noindex, a page error on load or first button press, anything fetched from outside, or no `window.__name` hook. checks.mjs runs it, so there is no need to hand-write a test script for a new draft. Give the draft's hook a `selftest()` that runs its maths on made-up data and returns true (or a string saying what is wrong); draft-check calls it, so the maths is checked on every run.
- To start the next run while a PR waits, use a worktree (`git worktree add ../runNN <sha>`) and run `npm ci` inside it. Never link node_modules into it: a linked node_modules got committed once, and copying that commit back replaced the real folder with a link to itself. checks.mjs fails if git tracks anything under node_modules.
- Don't run the browser suite and the benchmark at the same time on one machine: the benchmark reads answers on a timer and misses them when the CPU is shared.
- Void has a real say in its own direction (2026-10-08), as input, not a gate. After every deploy to main, Void is asked what it thinks of what shipped and how it would make it better; every day at 2:09 PM New York time (`.github/workflows/void-voice.yml`) it is asked where to go next, what feels weakest and which game to learn next. Its words are kept word for word (`/api/reflect`, `lib/voice.js`) and copied into `domains/void.voice.md`; never reword them. A small concrete ask also lands in the build queue as `voice:...`. Anyone can ask Void "what do you think of yourself?".
