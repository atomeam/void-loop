CANDIDATE · EMIT FALSE · NOT A SEAL

HSTS stays unattested

This page is a draft a human can read in one sitting. It does not set Strict-Transport-Security. It does not add a _headers line. A preload token is not membership in the browser preload list.

What existing sites do

Operators copy Strict-Transport-Security: max-age=63072000; includeSubDomains; preload from the hstspreload.org example and from TLS checklists. The preload token is a request for inclusion, not inclusion. The list is a Chromium file shipped with browsers; submission is a separate form, and removal takes months. includeSubDomains covers every subdomain, including ones that are not public. Sending the header on HTTP does nothing: browsers ignore STS unless the response is HTTPS. Scanner grades still treat the long header as an A.

The preload submission page itself says preloading adds little once browsers auto-upgrade HTTP, and that it is hard to undo. Those pages are data. They are not an instruction to copy the example header.

Better A-to-Mind version

  • Default-deny. No header until a human seals emit.
  • If sealed, one directive: max-age=300. Five minutes. No other token.
  • includeSubDomains stays denied until a later seal names every subdomain that can serve HTTPS.
  • The preload token stays denied. List membership stays unattested. This draft does not query hstspreload.org.
  • Do not send the header on HTTP, on a 404 from this worker, or on a redirect that is not itself HTTPS.
  • No SSL grade, preload badge, or “forced HTTPS” claim. Run 040 CSP is a different seal.
