## One-line

A sealed yield class hashes to an author-refusal id. The author sentence is discarded and is not in the hash. A yield mark is not authorship and not a transferred will.

## What current implementations do

Levels-of-automation panels and mixed-initiative products still collapse a joint step into one automation level, then render the next click as "approved" or "the agent did this." Runtime-authorization writeups in this window say agents form intent at the last second and that a log of what was authorized is the control. Shared-memory notes say co-operation rules are pulled up for later agents. Labor posts cite human-machine complementarities and treat a sign-off as the person still owning the call. A reply in the window assigns primary authorship to the human director and tool status to the generator. Those are claims. None of them is a hash that refuses the author sentence.

## Stricter Void version

- Default deny. The page has no agent execute, no shared-memory write, and no sign-off control.
- Yield class is a closed set: `catalog-step`, `hold`, `abstain`, `split-seat`, `local-only`.
- Canonical string is `yield-not-author|v1|<class>|author-refusal`. SHA-256 stays in the page. The worker refuses to hash.
- Author sentence is scratch. It is cleared on submit and is not in the hash.
- Disconfirm line is recorded as not hashed. It does not become a will transfer.

- Cloudflare-style worker sketch returns 403/404/405. Static file is enough to preview.

## Disconfirming evidence

A yield class would fail this draft if a sealed human later attested an author sentence that was stored in the hash. A catalog-step label would fail as transferred will if a pre-registered seat log showed one party both proposed and committed the step and that log were sealed as cession. This draft does not perform that test.
