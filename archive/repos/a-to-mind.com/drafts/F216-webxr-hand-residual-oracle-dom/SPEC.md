# F-216 WebXR Hand Residual Oracle DOM

**Novel combination:** True WebXR immersive session (hand-tracking preferred, progressive pointer + DeviceOrientation fallback) feeds a short trajectory history into a tiny residual predictor. Prediction error is the fitness signal for a population of pure-DOM oracle cards whose tiny genomes attempt local corrections. Weakest is mutated from the leader. Leader genome sealed to IndexedDB. No canvas particles, no WebGPU compute field, no reaction-diffusion, no spectral injection, no portal lattices.

**Branches away from:** the recent cluster of WebGPU particle/RD/neural-kernel fields, acoustic orientation swarms, codec-retina surprise oracles, causal portal attention, and orientation-genome competitions on continuous substrates (F208–F215). Moves the causal input to true WebXR hand poses and keeps embodiment strictly as competing CSS DOM cards driven by residual prediction error.

**Architecture:** single self-contained index.html; WebXR requestSession with hand-tracking optionalFeatures; main-thread residual history buffer + genome-driven correction; CSS absolute DOM oracles; IndexedDB seal; offline-capable, no external dependencies. Flat mode remains fully interactive.

**Expected:** Living competition of DOM cards that drift and scale according to how well their genomes reduce the residual of hand/pointer trajectory prediction. Enter XR for hand-driven mode. Seal persists the best genome across reloads.

**Failure modes:** no WebXR (flat pointer mode works); hand-tracking unavailable (viewer pose or pointer); IndexedDB blocked (in-memory only); low-end devices (6 agents fine).

**Building blocks:** WebXR hand as primary causal trajectory source, residual prediction error as multi-agent fitness, pure DOM oracle embodiment without particle or compute substrate, sealed genome. Next: full joint-pose features into the predictor or WebRTC DataChannel for cross-device residual sharing.
