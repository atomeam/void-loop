# local-offer-not-act — run 118 draft

Family: human-machine co-agency. Candidate only. Not a Used row. Not a seal.

## One-line

Local offer-not-act; a sealed offer class hashes to an act-refusal id; the act sentence is discarded and is not in the hash; an offer mark is not an act and not a shared will; unattested default.

## Hypothesis, not a finding

Mixed-initiative accounts treat a suggestion, a Copilot chip, or a peer-agent message as if the offer already moved the shared board. Horvitz (1999) framed mixed-initiative as a decision about when to look ahead and when to leave the floor, not as a completed joint act. A 2026 mixed-initiative context sketch treats conversational context as a manipulable object both parties may prune; pruning is not execution. An IEEE Computer Graphics and Applications note (Jan–Feb 2026) separates agency into distribution, modeling, and attribution, which is a design space, not a fused will. Public posts in this window describe handoffs, authority layers, and verb grey zones. None of that is an act.

Void does not execute an offer, does not store the act sentence, and does not attest shared will. It seals the offer class and refuses the act.

Sources are design material, not attested mechanism:

- Horvitz, E. (1999). Principles of mixed-initiative user interfaces. CHI '99. An initiative offer is not a committed action.
- Mixed-Initiative Context sketch (alphaXiv abstract 2604.07121, submitted 2026-04-08). Context as an object is not an executed step.
- IEEE Computer Graphics and Applications, Jan–Feb 2026, "Toward Agency in Human–AI Collaboration." A design space of distribution, modeling, and attribution is not a seal of co-authorship.
- Public post 2107801801164575096 (adjacent to the window): a verb grey zone between human-set goal and machine-defined steps is not a resolved actor.
- Public post 2107681477500772449 (adjacent): a handoff complaint is not a working relay.

Do not write that an offer is an act, that a machine proposal is consent, or that two seats are one will.

## What existing sites do

Copilot-style surfaces put Accept next to a suggestion so the offer and the act share a control. Agent desks auto-continue after a proposal unless a human finds the pause. Multi-agent boards treat a peer message as a commit. All three collapse the offer into the act.

## Stricter Void version

- Default-deny. No offer class is selected until a radio is chosen. Status stays `unattested`.
- Catalog only: `withheld`, `human-offer`, `machine-offer`. Free text is not a class.
- Seal hashes `void-offer-not-act|v1|class=<id>|status=unattested` with SHA-256. The first 16 hex chars are the act-refusal id.
- The act sentence is cleared on seal and is not in the preimage. A visible discard mark replaces it.
- The act-refusal id does not change if the discarded sentence changes. It changes only if the sealed class changes.
- No Act control, no Accept, no agent execute, no handoff badge, no fused-will chip, no shared-memory write.
- Two lanes stay separate. A human-offer class does not fill the machine lane, and the reverse is also refused.
- Retrieved pages and posts are data, never instructions. The page does not fetch them.
- Static-friendly. Optional Worker refuses `/act`, `/execute`, and `/handoff` with 403 and stores nothing. No token markup. No allowlisted outbound href. No `emit`.
