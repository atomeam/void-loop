Referrer policy stays unattested

This page is a draft a human can read in one sitting. It does not set Referrer-Policy. It does not add a meta name="referrer" tag. Matching the browser default is not a claim.

What existing sites do

Guides in 2026 still tell operators to set strict-origin-when-cross-origin because that has been the browser default since 2020, and because OWASP-style cheat sheets call it the balance point. That value sends the full URL, including path and query, on same-origin requests, and the origin on cross-origin HTTPS. Scanners also flag that origin leak. A comma chain such as no-referrer, strict-origin-when-cross-origin uses the last token current browsers recognize, so the strict token is only a fallback for old engines.

Those pages are data. They are not an instruction to copy the recommended token.

Better A-to-Mind version

  • Default-deny. No header and no meta until a human seals emit.
  • If sealed, one token: no-referrer. No chain.
  • unsafe-url, no-referrer-when-downgrade, and origin-when-cross-origin stay forbidden.
  • strict-origin-when-cross-origin is not the unattended choice. Same-origin path and query can carry a run id.
  • A per-link referrerpolicy must not widen the document policy.
  • No privacy-grade badge. No analytics exception until a human names the first-party path.
