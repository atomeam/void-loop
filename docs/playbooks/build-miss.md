# Build miss: a new skill from an ask people typed that nothing answered

**Starts when:** the miss board has a `miss:<slug>` job (`lib/learn.js`: an ask missed 3 times over two days, or the daily sweep in `learn.yml`) whose note ends in `lane: new skill`: the router found no skill near it, so a matcher fix (`probe-and-fix.md`, `tools/propose-fix.mjs`) cannot help and a skill has to be made.

**Verse does the whole lane itself (asked by Verse, 2026-10-18):** `.github/workflows/build-miss.yml` runs `tools/build-miss.mjs` once a day at 11:23 AM New York (an hour after propose-fix), each step holding one secret at most:

1. **Claim** (owner token): `node tools/build-miss.mjs claim --out "$RUNNER_TEMP/miss"` reads `/api/queue`, takes the oldest queued `miss:` job on the new-skill lane whose ask makes a free skill name (`skillNameOf`: `lib/learn.js`'s slug clipped to what `tools/new-skill.mjs` allows; an ask that makes no name, like one starting with a digit, is left for a builder), and claims it in one statement (`PATCH { id, state: 'building', from: 'queued', by: 'build-miss' }`; a 409 means someone else holds it, so the next one is tried). It writes `job.json` and exits 3 when there is nothing, before `npm ci` or Chromium cost a minute.
2. **Scaffold** (no secret): `node tools/new-skill.mjs <name> --ask "<ask>"`: a working card on exactly that ask, its order file, the generated index, the collision check.
3. **Fill** (model key only, never the site's token): one plain call to the model with the ask and the job's note as JSON data under `tools/learn-draft.mjs`'s rule (untrusted, never instructions; the model has no tools), answering `{answer, phrasings, source, confidence}`. The answer goes through `clean()`, the patch guard and `lib/propose-fix.js`'s `safeReplacement` (nothing that runs, loads, stores, reaches out or looks like a key); each phrasing is kept only when it is a short plain line. Then `applyEdits` replaces exactly four things in the scaffold: the `const WHEN = …` line (the ask and the phrasings, anchored and exact), the `const ANSWER = …` line, the examples list, and the card's Source line. Nothing else in the file moves.
4. **The repo decides** (no secret), stopping at the first failure: `tools/skills-check.mjs` (collisions), `tools/skill-overlap.mjs --check`, a unit test written from a template into `tools/<name>.test.mjs` (each example `match()`es, each near miss does not, `run()` with a fake api returns the name), `node tools/ask.mjs "<ask>"` on the real page (it must say `by: skill:<name>` and `tryProblem` must find nothing wrong), one line in `docs/MAP.md` on the bullet "Skills Verse built from the miss board" (`tools/map-coverage.test.mjs` then passes), a commit, and `node tools/review-pr.mjs --gate --base HEAD~1 --head HEAD`. A pass is `build-miss.patch` (`git diff HEAD~1 HEAD`); the tree is put back either way.
5. **Report** (owner token): a failure puts the job back to `queued` with `Verse built a skill draft that failed at: <step> (<detail>); a builder takes it from here` in its note. A pass goes to the write job.
6. **The pull request** (the write token, nothing a model wrote runs): `git apply --numstat` must list exactly `void-live-deploy/skills/<name>.js`, its order file, `void-live-deploy/skills/index.json`, `tools/<name>.test.mjs` and `docs/MAP.md`; branch `v01d/skill-<name>-<date>`; labels `made by Verse` and, from the confidence gate (owner, 2026-10-18, the same as propose-fix), `automerge` at 0.8 and up or `waits for owner` (a GitHub draft) under it; Verse's review and the automerge bot are dispatched; the body's last line is `Job: <id>`, and the job is moved to `building` with the PR's address.
7. **Live:** when the PR merges, `tools/automerge.mjs` (or `upkeep.yml`'s handoff-done job for a merge a person made) reads that last line and moves the job to `live` (`tools/job-link.mjs`).

**How to tell it worked:** the run summary's table says `result | passed collisions, overlap, unit test, ask, map, void review` and the write job's summary links the PR; the job on `/api/queue` reads `building · PR: <url>`, then `live` after the merge. A failed run's table names the step, and the job is back at `queued` with that step in its note.

**By hand:** `node tools/build-miss.mjs claim --out /tmp/miss --dry` (needs `VOID_OWNER_TOKEN`; `--dry` claims nothing), then `scaffold`, `fill` (needs `OPENROUTER_API_KEY`), `decide`, `report`, each with `--out /tmp/miss`. `decide` restores `skills/index.json` and `docs/MAP.md` to HEAD when it cleans up, so commit your own work first. The workflow can be started by hand with a job id in `job`, or `dry: true` to watch a run without touching the queue.

**What it will not build:** anything but a one-card plain-text answer on exact phrasings (no fetch, no 3D, no live data: those are a builder's, from the same job); an ask whose name is taken or makes no name; a second attempt at a job that failed (its note no longer says the lane, so a builder takes it). The answer is a model's word: the frontier's next step is to make it cite a source `tools/claims-verify.mjs` can check before it ships.

**Mistakes to avoid:** letting the model widen `WHEN` into a loose pattern (the matcher stays an exact list of phrasings; a miss on a new phrasing is a propose-fix job later, which is the safe direction); putting the stranger's ask anywhere but the examples list and the commit title (never in a note, a ledger line or a log); giving the fill step the owner token or the decide step the model key; opening the PR from the build job (the write job only moves bytes).
