# A rename: what the site calls itself changes everywhere a person reads it

**Starts when:** the owner renames Verse (2026-10-14: Verse became Verse; 2026-10-18: "Void is now Verse rename everywhere").

1. **Dry run first:** `node tools/rename-name.mjs --from <old> --to <new> --also <older word> --alt <old lower>=<new lower> --dry`. It prints every file it would change and what it keeps (owner quotes, the card mark, the revert trailer, camel-case joins). Read the joins: an identifier like `askVoid` stays; a product title like `VoidQuest` is a decision for the owner.
2. **Run it** without `--dry`. It changes the visible layer only: the page and its two deploy copies, skills, lib, functions, html pages, tools and tests (test strings follow the code), the bench asks, docs, domains, the workflows' display names, the agent skills, the extension and the action.
3. **What never changes by tool** (a live-data migration, the owner's call, each one a separate PR with a migration): identifiers, storage keys (`a2m.void.*`: every visitor's saved stage), D1 tables (`void_*`), secret names (`VOID_*`: GitHub and Cloudflare both), file and folder names (`void.html`, `void-live-deploy/`, `domains/void.*.md`), URL paths, the check name `void-review`, the repo name, the Pages project and the domain.
4. **By hand, every time:** the persona's first sentence (`lib/persona.js`: the new name, when the owner chose it, the old names people may still use); the card mark (`lib/card-share.js`: write the new mark, read the old one too); `tools/revert-target.mjs` VERIFY_WORKFLOWS keeps the old display names so runs from before the rename still count; any `old === 'Name'` normaliser in tools (film-post tags) maps the old names to the new one.
5. **Matchers:** `--alt v01d=verse` adds the new lower-case name beside the old one inside alternations `(?:void|v01d|verse|you)`, never in paths or ids (`lib/v01d-fixes`, `#v01d`). A name standing alone in a matcher (`/\bv01d\b/`, `/^v01d\s/`) becomes a group `(?:v01d|verse)`; prose on a line with no matcher is left alone. Old names keep matching: an ask is never un-learned. A line that must keep the old names (a history note, a both-name matcher, a list of old display names) ends with `// rename-name: keep` and the tool leaves it as written on every run; without it, a second run renames your hand edits (this happened twice).
6. **Regenerate**, never edit: families, guide, index, deps (finish.mjs's commit step runs them), `self.json`.
7. **Test what changed:** `node tools/rename-name.test.mjs`; the fast checks; in a real browser the sections that read the name back (`--only "Verse cards"`, `--only "self card"`); `node tools/ask.mjs "what do you think of yourself"` says the new name.
8. **Finish** with `node tools/finish.mjs grow "..." --test "Verse cards" ...`; the PR body lists what stayed (step 3) and asks the owner which of it to migrate.

**Mistakes already made (2026-10-18):** the first run renamed records (the decisions, the inputs and study notes, `grown.json`, the flake and site-test logs, the asks, the store changelog, `self.json`): reverted and added to the tool's skip list; a tag normaliser `t === 'Void' ? 'V01D' : t` became a no-op `t === 'Verse' ? 'Verse' : t` and had to be rewritten by hand (step 4); the append-only files (agent log, growth ledger, voice log) were never touched, which is right: the old lines keep the old name. Run the tool once: a second run rewrites the notes that name the old names on purpose (this playbook, the revert-target comment, the handoff line), so those files are on its skip list now.
