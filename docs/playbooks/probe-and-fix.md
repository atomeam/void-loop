# Probe and fix: grow a skill from the asks it misses

**Starts when:** an area answers badly (a miss on the board, a voice ask, a family the self-page calls weakest), or nothing else is queued.

**Verse does steps 1 to 5 itself (2026-10-15):** `.github/workflows/probe-asks.yml` (`tools/probe-asks.mjs`) has Verse's own model write 25 asks for its least proven family, probes them and queues the misses as `probe:` jobs; an hour later `.github/workflows/propose-fix.yml` (`tools/propose-fix.mjs`) takes the oldest `probe:` job, has the model propose the narrowest matcher change to the owning skill (owner-only `/api/propose-fix`, exact line replacements only), and lets the repo decide: `tools/skills-check.mjs`, the skill's unit test, `tools/review-pr.mjs --gate`, and the benchmark on the ask plus every bench ask the skill already answers. A pass becomes a pull request labelled "made by Verse" (never automerge: a builder reviews it like anyone's); a fail leaves the job queued with the failing step in its note, for a builder at step 3. The asks Verse wrote are never committed, so write your own paraphrase at step 6 if the fix earns a bench line.

**A stronger brain for a hard one (owner, 2026-10-16):** when Verse's own model keeps proposing fixes that fail, start `propose-fix.yml` by hand with `brain: claude` (and the job id in `job`, or empty for the oldest). Claude gets the same question in one capped call (`tools/claude-brain.mjs`: 8,000 output tokens, about $0.20 at most; the monthly API credits pay for it, so keep a spend limit on the organization). How to tell it worked: the run summary's table says `brain | claude-opus-5-5 ($…)` and the result row says passed. Mistakes to avoid: never add the key to the scheduled run, the site or the pull-request job; never paste it anywhere but the repo secret. Locally: `ANTHROPIC_API_KEY=… node tools/propose-fix.mjs --ask "…" --skill <name> --brain claude` (always dry).

1. **Write 20–30 asks** in one area, the way people type them (typos, short forms, "how many cups is 500g of flour"), each `{ "ask", "want", "says" }` in the shape of `tools/bench.json`. Paraphrases only, never a visitor's exact words (the repo is public).
2. **Probe:** `node tools/bench.mjs --probe asks.json` prints only the misses. The bench stubs places (every place is Paris), countries and Datamuse, so a `says` there can only check who answered.
3. **For each miss, find who answered:** `node tools/ask.mjs "the ask"` shows the skill, the card text and any page error.
4. **Fix in the owning skill's matcher**, not in a new skill, unless no skill owns the area. Keep every new phrase narrow: run the old asks of that skill again only if the matcher you touched is shared.
5. **Re-probe the misses:** `node tools/bench.mjs --again`. A wrong expectation is a fix to the ask, not the skill.
6. **Add the batch:** `node tools/append.mjs bench --skip asks.json`.
7. **Ship:** grow line, agent-log line, `VOID_SKIP_BENCH=1 node tools/checks.mjs`, `node tools/push.mjs`, PR with automerge.

**Mistakes already made:** a broad rewrite rule broke "how many miles is 10k" (restrict rewrites to known unit words); "sunscreen" in one skill's matcher stole another skill's example (run `node tools/checks.mjs`, it checks collisions); a weather matcher took "medium rare steak temperature" (exclude the other domain's words).

**Missed asks are a queue with two lanes (asked by Verse, 2026-10-16):** a `miss:` job's note ends in `lane: propose-fix` when the router named a skill that should have caught the ask (`router skill:<name>`), and `lane: new skill` when nothing was near. `tools/propose-fix.mjs` takes the oldest `probe:`, `route:` or propose-fix-lane `miss:` job by itself; the new-skill lane is Verse's too since 2026-10-18 (`build-miss.md`: `tools/build-miss.mjs`, `.github/workflows/build-miss.yml`, an hour after this one), and a job it fails on goes to a builder (`docs/UPGRADING.md`). Every proposal carries a `risk` (`low`, `medium`, `high`, worked out from the edits by `riskOf` in `lib/propose-fix.js`, never from the model's word): an edit on a structural line is high and the card on "Verse's fixes" says so. A fix under 0.8 confidence opens as a GitHub draft with the `waits for owner` label; Approve adds `automerge`, which makes it ready and merges it once Verse's review is clean.

**Mistake made (2026-10-23, found by reading the runs, not the summaries):** every `propose-fix` run for ten days ended "nothing to fix today" with a green tick, while the log said `POST /api/propose-fix: HTTP 413 too big`: the tool sent the skill's whole file, the route's guard caps the body at 40,000 bytes, and the early exit never marked the job failed, so the same four over-size `probe:` jobs sat at the cap (`PROBE_OPEN_MAX` 4) and `probe-asks` queued nothing new ("16 more misses wait"). Now the tool sends a window (`sourceWindow`: the head and the tail, where `match()` lives, within `MAX_SOURCE`) and every early exit files the job as failed with the reason. The lesson: a loop step that swallows its own error into exit 3 "nothing to do" hides starvation; read one real log a day.
