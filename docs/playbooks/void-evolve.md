# The Forge: an evolutionary loop for Verse's routing

**Starts when:** a builder or a Verse agent runs one command (`node tools/void-evolve.mjs`). It is deliberately not on a timer: `grow-self.yml` already owns the daily page-probe → benchmark → PR lane, and a blind timer would open data-only PRs that buy no growth. Run the Forge when there is a skill worth hardening (a weak family, a new routing gap, an ask somebody missed), or from a `probe:` job.

**Why it exists:** `lacks.mjs` ranks what is least proven and `grow-self.yml` banks phrases the page already answers, but neither *competes* several ways of fixing a gap against each other. The Forge makes candidates, scores them on the same stress suite and the same immutable bank, and keeps only a survivor. Test count grows with capability: every page-proven ask a champion wins is appended to the bank, so the next cycle inherits it as a regression.

0. **Discover** (`weakest()` in `tools/void-evolve.mjs`, `neighbors()` in `tools/evolve-adversary.mjs`): pick the skill with the fewest benchmark rows and examples, then its most confusable neighbours (skills whose example words overlap its own). Those neighbours are the adversarial surface.
1. **Stress** (`tools/evolve-adversary.mjs`): from each skill's own examples generate near-miss collisions, polite fillers, colloquial verbs, punctuation, boundary prompts and multi-intent asks — five families, deterministic, no model and no network. An LLM generator can be injected later through `synthesize` / the `--skill` seam; everything downstream only sees `{ ask, want, kind }` rows.
2. **Mutate** (`tools/evolve-mutate.mjs`): three candidates from the asks the baseline missed — conservative (anchored exact phrases), adaptive (content-word regex), synthesis (one alternation). Candidates are *data*, applied to an in-memory router, never to a file or a branch: that is the sandbox, and it makes a cycle cheap and reversible.
3. **Tournament** (`tools/evolve-tournament.mjs`): every candidate runs the same suite and bank. Kill switches first — a newly broken banked ask, a match needing ten skills, more than five turns or eight reads scores exactly zero. Survivors are scored on the owner's formula, each term normalised to [0,1]:
   `accuracy * 0.5 + tokenEfficiency * 0.2 + (1000 / speed) * 0.2 + (12 - readDepth) * 0.1`.
   `tokenEfficiency` is one minus the entropy tax (long regex dumps and many patterns are penalised), `speed` is latency, `readDepth` is the target's average position among the focused skills. Accuracy counts the target's own cases; a neighbour's case stolen by a mutation counts as a regression.
4. **Promote** (`tools/evolve-merge.mjs`): a champion's wins are *proposals* (`report.proposed`) until the real page proves them. The orchestrator never banks a simulated match. `--proof` takes asks answered by `tools/bench.mjs --probe`; only those enter `tests/immutable-regression-bank.json`. `--apply` records an append-only packet at `domains/void.evolve.promotions.json` and prints the PR body; `--pr <n>` labels an existing PR for automerge. The bank's first `seedCount` rows are pinned by a digest — editing or dropping a legacy ask fails validation and the PR is refused.
5. **Ship:** the champion's patterns are applied to the skill by the normal builder lane (the same one that fixes any routing gap), then `tools/checks.mjs --changed`, Verse's review and the full suite decide. The Forge never merges on its own: automerge still waits for a clean review and a green suite, exactly like every other PR.

**How to tell it worked:** `node tools/void-evolve.mjs --dry --skill throw-off` prints `champion <strategy> (<fitness>), proposing <n> for page proof` with one line per candidate; the losing candidate's reason is its `broken` or `entropy` number. `node tools/checks.mjs --only evolve` runs the six fast checks. After a real cycle, `domains/void.evolve.json` holds every report and the replay command reproduces it.

**Mistakes this avoids:** counting a pattern's length as "turns" (it zeroed every good candidate — turns are an agentic budget, default 1 in a local cycle); measuring `readDepth` across all 393 skills (a skill at rank 720 always tripped the depth kill switch — measure within the target + neighbours); treating a simulated match as proven (only a page probe banks an ask); duplicating `grow-self.yml` (the Forge decides, that lane already banks page-proven phrases).

**What it will not do:** edit a skill, open a PR on a timer, spend a token, read a secret, or bank an ask the page has not answered. It does not replace `lacks.mjs` (discovery ranking), `grow-self.yml` (page proof and PR) or `finish.mjs` (ledger and commit); it sits between them and makes the choice evidence-based.
