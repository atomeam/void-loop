# Subject cards: an ask for a thing becomes a card made for that thing

**What starts it:** someone asks for a name (a character, a person, a place, a song, a chess opening) and the card is wrong: it says "Answer - from a source" over a refusal, shows a neighbour's page, draws a picture from one word of the ask, or has the same frame as every other card. Owner, 2026-10-26: "happy time harry", "it should do that with all things like that".

**The commands:**
1. Reproduce with `node tools/subject-eval.mjs --only "<the ask>"` (the sandbox has no network, so add a fixture to `tools/fixtures/subject-eval.json`: the Wikipedia replies the ask would meet, the model's canned words, and `expect`). Open the screenshot it saves (`/tmp/subject-eval/eval-<ask>.png`) and say what it shows.
2. Where it breaks: a refusal body is `lib/no-answer.js` `isNoAnswer`; a name inside a list page is `functions/api/answer.js` `sectionSource` (redirect fragment, then full-text section hit); the kind comes from `lib/card-kinds.js` KINDS (the fetched description first); the frame, badges, notice and photo kind are one row in `lib/subject-kinds.js` `SUBJECT_KINDS`; the picture's motif words are `lib/card-subject.js` MOTIFS and DRAW.
3. A new kind of subject: add its row to KINDS and SUBJECT_KINDS (the test `every kind ... has a row` fails until both exist), its CSS theme in `lib/card-frame.js` CARD_CSS if it is a new theme, and 1 to 3 fixtures. `node --test tools/subject-kinds.test.mjs tools/no-answer.test.mjs`, then `node tools/subject-eval.mjs`.
4. Real photos only through `lib/free-pics.js` (`picFor` in answer.js), searched by the fetched source's own title, with the credit and the "Archive photo" label; never a person, never a fictional character, never the visitor's words.

**How to tell it worked:** every fixture passes (`35/35 pass`), the screenshot of the card shows what the ask is about (a doll for a doll, a postcard for a place), a refusal shows "Not found" with no "Adds to Verse" and no sources, and `tools/card-share.test.mjs` still round-trips the code line.

**Mistakes made (read before changing):** `kindOf` returned the catch-all "Idea" for any description because the last row matches everything; the mobile CSS hid the whole `.vc-adds` block (it holds the badges and the "not affiliated" line now, so only its text is hidden there); Playwright runs the LAST registered route first (register the catch-all before the specific stub); a one- or two-word ask never reached `/api/answer` (the page's own `showArticle` took the first Wikipedia hit, however fuzzy), so that path now hands a thin match, or no match, to the answer route; "red panda" and "blue whale" are taken by the clock skill (a colour and a word read as a time), still open; the fixtures are stubs of Wikipedia's reply shapes written from memory, not live replies: confirm a real redirect with `action=query&redirects=1&titles=<name>` when the network is open.
