# A growth-inbox health line: show a new fact about the skills where Verse reads its inbox

**Starts when:** Verse asks for a status, metric or dashboard "in the growth inbox" or "on the owner page" about its skills (flag a failing one, map a health file, track a streak, mark a mismatch). The inbox is the growth card (`skills/growth.js`: friction, owner view, better) plus the build queue (`/api/queue`, mirrored in `domains/void.queue.md`).

1. **Find the fact in a file the repo already writes**, never a new tracker: `skills/families.json` (ratings, `smoke`, `promoted`, `streak`, `smoke_at`), `tools/skills-smoke.json` (the daily router test), `void.better.json` (day over day), `fringe/ledger.json`, the ledger (`void.growth.json`), `/api/reflect` `follow.recent` (asks beside what was built). If a new per-row fact is needed, add it to `tools/families.mjs` (`docs/playbooks/manifest-field.md`).
2. **Write the line as a pure function in `void-live-deploy/lib/inbox-health.js`** (`skillStatus`, `familyMapHtml`, `promotedRows`, `bloomPlan`, `diverge` are the shape): data in, escaped HTML out, one `esc` on every value, an empty string when there is nothing to say.
3. **Unit test it** in `tools/inbox-health.test.mjs` with markup in a skill name (`Al<pha>`): it must come out escaped.
4. **Hook it into `skills/growth.js`** next to the line it belongs under (`.growth-owner`, `.growth-better`), by `insertAdjacentHTML('afterend', …)` with a `void-review: ok:` note that the helper escapes. Add to its `suite()` if it is a number.
5. **Browser section** in `tools/test_void.mjs` that stubs the files with route stubs (`fresh(() => { delete Navigator.prototype.serviceWorker; })`, then `ctx.route`), asks `growth`, and reads the line back. Run only it: `node tools/heavy.mjs node tools/test_void.mjs --only "<section words>"`.
6. **Work for the inbox**: a signal that should become a job gets a tool like `tools/review-main.mjs` / `tools/fringe-novelty.mjs`: one open job at a time, a target prefix (`review:`, `novelty:`), never queued twice, the owner token from `VOID_OWNER_TOKEN`, a quiet no-op without it, a step in `.github/workflows/review-main.yml`.

**Mistakes already made:** a number computed from a truncated ledger line (160 characters) over-flags divergence, so show the words, not a verdict; counting how often people use a skill breaks the owner's no-behaviour-tracking rule, so a last-used day lives only in the person's own browser (`lib/skill-use.js`); a check keyed on a function name the page then lost to `skills/` fails on every run (`tools/moved-check.mjs` finds those).
