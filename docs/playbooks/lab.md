# Lab: the lab repo's experiments, live and tested

**Starts when:** every day at 3:37 AM New York time (`.github/workflows/lab-sync.yml`), or by hand: `gh workflow run lab-sync.yml` (`all` re-imports and re-tests every draft). Or locally, after a change to the wrapper in `tools/lab-import.mjs`: `node tools/lab-sync.mjs --drafts <a clone's drafts folder> --all`.

**Why it exists:** the owner, 2026-10-29: "get all these live and working too". A lab repo (github `atomeam/a-to-mind.com`, folder `drafts/`) makes a standalone single-file HTML experiment every hour (about 2 MB for 246 of them, no outside dependencies). They sat in a repo nobody opened. Now each is a page of Verse, tested before it goes up.

## The steps

1. **Pull** (`tools/lab-sync.mjs`): `git clone --depth 1 https://github.com/atomeam/a-to-mind.com`, or `--drafts <dir>` for a folder you have. Only drafts with an `index.html` count; the others hold a `proposed-index.html` diff and are ignored.
2. **Import** (`tools/lab-import.mjs`, pure parts tested in `tools/lab-import.test.mjs`): each draft becomes `void-live-deploy/lab/<slug>/index.html` (slug = the folder name lowercased). Every inline executable `<script>` moves to `app.js` beside it (`app-2.js` for more), `type="module"` kept as it was. The deploy adds one `_headers` rule per page that has an inline script (`tools/csp-hashes.mjs`) and Pages stops at 80 rules, so 246 inline pages would break the deploy; an external same-origin script needs none. Files beside the page that it names (`core.js`, a worklet) are copied. The head gets the title (`<SPEC first heading> · Verse lab`), description (SPEC's first prose line, after "Concept"), canonical, share card, the shared `/lab/lab.css` and the visit beacon; the body gets a hidden `<h1>` when the page has none and a small footer (back to `/lab/`, "Ask Verse anything"). Title and blurb are never invented: SPEC first, then the page's own `<title>` and description, then the folder name. Text a person reads says Verse, not the old name (`rename`: capital `Void` and `V01D` in text nodes, titles, blurbs and script strings, never in tags, ids or CSS, never the lowercase void). Every page carries `<meta name="verse-handoff" content="in: none; out: none">` (`tools/handoff-scan.mjs` wants one on every page; run `node tools/handoff-scan.mjs --write` after a new kind of page). A draft cut off mid-script (a `<script>` that never closes) is not a page.
3. **Open each one** (`tools/lab-probe.mjs`): headless Chromium, served with the site's real `_headers`, load, wait 2 seconds, click and drag once, wait again. It records uncaught errors, console errors, failed or 4xx requests, and whether a screenshot has more than one flat colour. `classify` gives the status: `works`; `needs-webgpu` or `needs-webxr` (the source uses `navigator.gpu` or `navigator.xr` and has no 2D or WebGL path, or its errors all name the missing graphics or headset: headless Chromium has neither); `broken` (a code error such as `x is not defined`, a syntax error, or a blank page).
4. **Publish** the ones that run; a needs-* page also loads `/lab/needs.js`, which says plainly that this browser lacks WebGPU or WebXR instead of leaving a blank page (a wrapper only; the experiment's code is never edited). `void-live-deploy/lab/catalog.json` has slug, title, blurb, status, the error for broken ones and the draft's fingerprint; `void-live-deploy/lab/index.html` is the gallery (static, newest F-number first, no script); the sitemap lists every published page (`tools/sitemap.mjs` reads the catalog); `/tools/` links `/lab/`.
5. **Queue the broken**: not published, one line each in `domains/lab.broken.md` (slug, the draft's path, the error, what to try first). A fixer fixes the draft (in the lab repo, or a copy) and runs `node tools/lab-sync.mjs --drafts <dir> --only <slug>`; once it runs it is published and leaves the list.
6. **Pull request**: the workflow commits `void-live-deploy/lab`, the sitemap and `domains/lab.broken.md` to `lab/sync-<time>`, opens a PR labelled `made by Verse` and `automerge`, and starts Verse's review and the automerge bot (a PR a token opens starts no `pull_request` runs).

**After changing the wrapper** (the footer, the head, the notice): `node tools/lab-import.mjs --drafts <drafts dir>` re-writes every published page the way it was tested (the catalog says which are broken and which get the notice) without opening a browser again.

**How to tell it worked:** the run summary says `lab-sync: N tested {"works":..,"broken":..}`; `node --test tools/lab-import.test.mjs` is green (it checks every catalog entry against its folder, that no published page has an inline script, and that every broken entry has its line); open `/lab/` and three experiments and look at them.

**Mistakes already made:**
- Counting WebGPU use in the source as proof that a page cannot run: 59 drafts mention `navigator.gpu`, most with a Canvas2D fallback that paints fine. A page is `needs-*` only when it has no fallback or its errors are about the missing hardware.
- Hiding code errors behind `needs-*`: a syntax error in a WebGPU page is `broken`, not "needs a GPU".
- The site's `Permissions-Policy` blocks accelerometer, gyroscope and magnetometer, so every tilt experiment printed a violation. `/lab/*` has its own rule in `_headers` that allows the page itself to use them (`! Permissions-Policy` detaches the site-wide one first).
- Hash rules: do not leave one inline script on a lab page; the catalog test fails if you do.
- A draft file cut off mid-write (`f205-rd-attention-kernel`) passed a load test but had its script still inline; `unfinished()` now stops it at import.
- The probe taught nothing about touch: it clicks and drags with a mouse. Experiments that need a phone's tilt only show their first frame here.

**What it will not do:** edit an experiment's logic, delete a published page (a page that later breaks stays until a person removes it; the sync says so), or publish a draft it could not open.
