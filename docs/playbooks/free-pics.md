# Real, free, properly licensed pictures (lib/free-pics.js)

**What starts it:** a card or page that would be better with a real picture (a league header, a venue, a planet, a painting, an animal) and has a vetted subject to search for. The evidence, ranking and licences are in `docs/free-pictures.md`.

**The commands:**
1. In a Pages Function: `import { findPictures, creditSegments, creditHtml } from '../../lib/free-pics.js'`, then
   `const pics = await findPictures('epl', { kind: 'league', date, max: 3, env, fetch, cap: (k, l) => cap(env, k, l) })` (`cap` from `lib/daily-cap.js`). The subject is a key on `SUBJECTS`, a word on `GENERIC`, or text taken from a fetched answer with `fromAnswer: true` (a team or venue name from a feed). A visitor's own words are never passed: anything else returns `[]` with no request.
2. `kind` picks the sources and their order: `sport` / `league` / `team` / `event` / `venue`, `player` (people: no stock sources), `place`, `space` (NASA first), `art` (Met, Chicago, Cleveland), `animal`, `history` (Library of Congress first).
3. Show the picture with its credit, always: `creditHtml(pic)` (HTML, every part escaped) or `creditSegments(pic)` (text nodes), plus a report link (`mailto:` in `lib/daily-photo.js` `reportHref`). Label `pic.archive === true` as an archive picture. `pic.hotlink === false` (Pixabay) means copy the bytes, do not hotlink. Always keep a drawing as the fallback: `[]` means nothing qualified.
4. `/api/daily-art` photo mode already calls it after Commons, Openverse and Flickr found nothing, with the league's own closed subject. **The "happy time harry" card builder (agent a3c9add389e311a8d) should call `findPictures(subject, { kind: 'place' | 'venue' | 'animal' | 'art', fromAnswer: true, ... })` from its own Function for the card's subject picture and render `creditHtml`.** Nothing in its files was touched here.
5. Owner switches: `FREE_PICS_OFF=1`, `FREE_PICS_<ID>=0` (e.g. `FREE_PICS_LOC=0`), `FREE_PICS_DAY` (global daily cap, default 400). Keys (GitHub and Cloudflare secrets only): `PEXELS_API_KEY`, `PIXABAY_API_KEY`, `UNSPLASH_ACCESS_KEY`, `SMITHSONIAN_API_KEY`, `EUROPEANA_API_KEY`, `FLICKR_API_KEY` plus `FREE_PICS_FLICKR_COMMERCIAL=1` only with a commercial key, `OPENVERSE_CLIENT_ID` + `OPENVERSE_CLIENT_SECRET`.
6. Tests: `node --test tools/free-pics.test.mjs`. Live check: run the workflow **Free pictures probe** (`.github/workflows/free-pics-probe.yml`), read `domains/free-pics.probe.json`.

**How to tell it worked:** the probe shows every keyless source `works` with accepted > 0; a picture always has author (unless CC0/public domain), licence with link, and source page; NC/ND/unknown are refused with a reason; the second ask of a day is a cache hit (no network).

**Mistakes made (read before changing):** the sandbox cannot reach any source, so parsers were written from documentation and fixed from the probe's output; Europeana and Internet Archive give licences as `http://` addresses (the https-only helper dropped them); the Library of Congress blocks a caller for an hour above 20 requests a minute and answers a CAPTCHA page when busy (a non-JSON answer rests the source for an hour; the budget is 6 a minute site-wide); a free Flickr key is non-commercial (confirm), so Flickr stays off without `FREE_PICS_FLICKR_COMMERCIAL`; Unsplash asks for a download ping and its own image addresses (done, hotlinked); Pixabay asks that images not be hotlinked (confirm), so the route copies them.
