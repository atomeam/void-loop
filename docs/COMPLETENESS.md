# Completeness: the basics every game must have

Adam played The Landlord's Game (our property-trading game) and found no money section and no property section. Money was a single
line of text, and property showed only as coloured ticks on the board. He suspected the rest of the site had the same gap. This file
tracks the basics a player expects from the best version of each game, what was missing, and what is fixed. Nothing is removed here.
Features are only combined or added.

| The Landlord's Game and VoidQuest | deeds as cards: "Save to my cards" stores a deed in the shared card shape (`kind: 'deed'`, title, fields) in `verse.cards` and fires `verse:card-save` so the universal card binder can pick it up | yes (the binder side is still being built) |

## How Verse finds what nobody thought to check

The goal is for Verse to check things it can't think of yet. It does that five ways. Every check joins `tools/checks.mjs`, and logs
count topics only, never anyone's words.

1. **General rules from every miss** (`tools/completeness.mjs`, `RULES`). Each rule records the miss it came from. The property-game
   miss became two rules that run on every game: "a game with a currency shows each player's balance in its own panel" and "a game
   where players hold things lists what each holds".
2. **Expectation mining** (`tools/expectations.mjs`). Verse passively studies a game's manual or a leading site's page on the owner's
   machine (`tools/rea-study.mjs`, `tools/study-engine.mjs`). It pulls out the features players expect, compares them with Verse's code
   and files each gap as a topic-only want ("chess: timer"). With `--learn`, the gap becomes a general rule in
   `tools/completeness-rules.json`, and that rule then runs on every game. Studied text and sources stay in `~/.verse-private/`, never
   in this repo.
3. **Persona playtests** (`tools/persona-playtest.mjs`, a browser check). A headless browser opens every game as four kinds of player:
   - **New player:** is there a "how to play"?
   - **Phone:** does the card fit a 390 px screen?
   - **Keyboard:** can the card be reached with the keyboard alone?
   - **Screen reader:** does every control have a name, and is the status announced?

   Every persona also checks for cut-off text and page errors. Screenshots are saved with `--shots`.
4. **Cross-skill analogy** (`analogies()`). A basic that at least half of the similar games have, but one game lacks, is reported as
   a gap.
5. **Mutation and fuzz testing** (`fuzz()`). Every example ask is changed (case, padding, punctuation, a typo, filler words, an emoji,
   an empty ask). Matching must never throw, and near misses must stay out.
