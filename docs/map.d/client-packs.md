The client packs, each a card offline that says what Verse takes on for a business process: `skills/ownership-pack.js` (what Verse owns and what the client keeps), `skills/automation-pack.js` (the automations Verse would run for a process), `skills/automation-proposal.js` (proposes concrete automations Verse will own for a process) and `skills/process-map.js` (maps a business process end-to-end and marks where Verse owns the heavy lifting), `skills/lift-summary.js` (a short client summary of the systems Verse owns and the work that drops), `skills/docs-pack.js` (the client documentation for a system: status, ownership, monitors, next steps) and `skills/feedback-loop.js` (client feedback on a shipped slice turned into the next change). `skills/reuse-tools.js` (lists run 16) is one family of `reuse-pack` and `connect-pack`, the existing tools to reuse before building; both names still answer and `tools/reuse-tools-family.test.mjs` keeps every ask on the member it reached before. `tools/versus-useful.mjs` is the "is it real and useful?" check: a phone-width visit judged by a free model, and a missing model counts as no.

`skills/client-status.js` (lists run 18) is one family of `skills/client-status-pack.js` and `skills/delivery-board.js` (the delivery-board skill: "delivery board for ...", "client board on ...", ownership, progress, monitors and the next handoff on one client board, its progress read live from /api/status and /incidents.json); tools/client-status-family.test.mjs.

`skills/status-digest.js` (lists run 19) is the client status family's third member: "status digest for ...", "client digest: ...", "weekly status for ...", a short digest read live from /api/status and /incidents.json.

`skills/time-saved.js` (#2729, lists run 24 gave it its order file) is the client pack that estimates the hours a client no longer spends on a process once Verse owns its systems, monitors, tests and handoffs: "time saved for the invoice automation", "client time saved: support router"; an estimate from typical process load, never claimed as measured.

`skills/reliability-pack.js` packages the suggested monitors, verification checks, the live status reading from /api/status and /incidents.json, and the incident path for a system: "reliability pack for the invoice automation", "SLA pack for onboarding"; nothing is claimed as already measured, and a reading that did not answer is named.

`skills/system-design.js` (the design step before the packs): "design the system for client onboarding", "system design for invoice reminders", a rules-based design of the systems, automations, tests, monitors and handoff points Verse will own, reusing the existing packs. `skills/connect-flows.js` maps the data flows and handoff points between the systems: "connect the systems for invoice reminders", "show the data flows for client onboarding". `skills/handoff-ready.js` checks whether a system is ready to hand to a client ("is this system handoff ready", "what is missing for client handoff on the status reports") across ownership, status, docs, monitors and automations. `skills/summon-pack.js` packages the exact asks a client types to summon live status, ownership, progress, time saved and the next handoff ("summon pack for the invoice automation", "how does the client summon the support router status"). Each is offline and rules-based; nothing is sent.
